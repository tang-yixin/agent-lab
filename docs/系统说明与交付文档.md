## 1. 系统概述

本系统是一个由 **Agent 驱动** 的 MovieLens 1M 数据治理系统。用户在前端输入自然语言请求，
Agent（基于 DeepSeek 大模型的 function calling）自动理解意图，调用 Hadoop MapReduce
工具完成 **数据检查 → 清洗前评分 → 数据清洗 → 清洗后评分 → 结果对照与解释** 的完整流程，
全程无需用户手动运行 Hadoop 命令、上传中间文件或逐阶段点击按钮。

### 1.1 技术栈

| 组件 | 选型 | 说明 |
| --- | --- | --- |
| 大数据框架 | Hadoop 3.4.1 | Docker 容器，单节点伪分布式 |
| 计算引擎 | Java MapReduce | Maven 构建，编译 target 1.8 |
| Agent | DeepSeek API（function calling） | OpenAI 兼容接口 |
| 后端 | FastAPI（Python 3.13） | 托管前端 + /chat 等接口 |
| 前端 | 原生 HTML/JS + Chart.js + marked | 无构建步骤 |
| 数据 | ml-1m | movies / ratings / users 三表 |

### 1.2 总体架构

```mermaid
flowchart LR
    U[用户] -->|自然语言| FE[前端 HTML/JS]
    FE -->|POST /chat| BE[FastAPI 后端]
    BE --> AG[Agent 核心<br/>DeepSeek function calling]
    AG -->|调用工具| TOOL[Hadoop 工具封装<br/>hadoop_tools.py]
    TOOL -->|docker exec<br/>hadoop jar| HD[Hadoop Docker 容器<br/>Java MapReduce]
    HD -->|执行状态+结果| TOOL
    TOOL -->|结构化 JSON| AG
    AG -->|解释/回答| BE
    BE -->|JSON| FE
    HD -->|读写| HDFS[(HDFS 数据)]
```

详见项目根目录 `README.md` 第 4 节「快速开始」。核心步骤：

## 3. 工具接口说明

Agent 通过 function calling 暴露以下工具，均为「封装 Hadoop 能力」的可调用接口：

| 工具 | 参数 | 功能 | 对应 MapReduce |
| --- | --- | --- | --- |
| `score_data` | `input_path`, `output_path` | 对数据做五维质量评分，返回得分+计数 | `lab2.ScoreJob` |
| `clean_data` | `input_path`, `output_path` | 清洗（修复/去重/隔离），返回处置统计 | `lab2.CleanJob` |
| `read_quarantine_samples` | `output_path`, `limit` | 读取隔离记录样例 | （读 HDFS） |

### 3.1 工具实现机制

每个工具内部通过 `subprocess` 执行 `docker exec lab2-hadoop sh -c "hadoop jar ..."`，
触发容器内的 MapReduce 作业，再从 HDFS 读回结构化 JSON。**Agent 不直接接触数据，
清洗与评分实际由 Hadoop 执行**，满足题目要求。

### 3.2 MapReduce 作业

| 类 | 职责 |
| --- | --- |
| `DataRules` | 共享规则：合法编码集、时间戳范围、T1/T2、字段判定 |
| `ReferenceTables` | 加载合法 ID 集合，用于跨表一致性检查 |
| `ScoreJob` | 五维评分（计数作业 + 去重作业），输出 `report.json` |
| `CleanJob` | 清洗（修复/去重/隔离），输出分目录数据 + `summary.json` |

### 3.3 后端 HTTP 接口

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `/chat` | POST | 自然语言请求，返回 Agent 回答 + 工具调用步骤 + **task_id** |
| `/health` | GET | 健康检查 + key 配置状态 |
| `/report` | GET | 完整评估报告（评分/统计/版本/T1T2） |
| `/samples` | GET | 清洗后数据样例 + 隔离样例 + 记录数 |
| `/reports` | GET | 历史报告文件名列表 |
| `/report-file/{filename}` | GET | 单个历史报告的完整内容 |
| `/` | GET | 前端页面 |

### 3.4 任务标识与报告归档

- 每次 `/chat` 请求生成唯一 **task_id**（UUID），随响应返回并在前端展示；
- 任务完成后，完整报告**自动归档**到本地 `reports/task-<id>-<时间戳>.json`，实现历史留存与追溯；
- 版本信息（`raw/rules/scoring/timeboundary`）从 `config/version.json` 读取，规则变更时改配置文件即可递增版本号，无需改代码。

## 5. 实验配置

### 5.1 五维评分方案（scoring-v1.0）

统一口径：每维 0–100 分，清洗前后用**完全相同**的公式，保证可比。

| 维度 | 衡量定义 | 公式 |
| --- | --- | --- |
| Accurate | 字段值是否真实合法 | 合法记录数 / 总记录数 × 100 |
| Complete | 必填字段是否非空 | 非空字段数 / 应存在字段总数 × 100 |
| Unique | 业务记录是否唯一 | (1 − 重复记录数 / 总记录数) × 100 |
| Up-to-date | 时间戳是否在覆盖范围 | 合法时间戳记录 / 应有时效性记录 × 100 |
| Consistent | 格式/单位/跨表是否一致 | 一致记录数 / 总记录数 × 100 |

综合分 = 加权平均：Accurate 0.25、Complete 0.25、Unique 0.20、Consistent 0.20、Up-to-date 0.10。

**设计依据**：准确性/完整性直接决定可用性，权重最高；时效性受数据集本身年代限制（2003 年发布），改善空间有限，权重最低。

### 5.2 清洗规则（rules-v1.0）

三类处置：**修复（fix）**、**去重（dedup）**、**隔离（quarantine）**。

| 编号 | 问题 | 处置 |
| --- | --- | --- |
| R1 | 分隔符异常（逗号/竖线/冒号） | 修复为 `::` |
| R2 | 字段数错误 | 修复（丢弃 EXTRA_FIELD）或隔离 |
| R3 | 评分非整数/越界/空 | 隔离 |
| R4 | 时间戳毫秒级 | 修复（÷1000 转秒） |
| R5 | 时间戳超范围/非法 | 隔离 |
| R6 | 完全重复记录 | 去重 |
| R7 | 同键不同值冲突 | 隔离 |
| R8 | 编码非法（Gender=X、Age=30、Occ=99、UnknownGenre） | 隔离 |
| R9 | 空字段/空标题 | 隔离 |
| R10 | 跨表引用不存在 | 隔离 |
| R11 | 时间戳缺失 | 隔离 |
| R12 | 标题无年份/异常 | 隔离 |

## 7. 已知限制

1. **隔离 ≠ 修复**：155,503 条隔离/冲突记录被移出主数据集单独存放，其数据问题本身未解决，待人工复核。
2. **满分是「幸存者偏差」**：清洗后五维满分，仅代表「在既定规则下、对保留记录」达标，主要贡献来自「剔除」而非「修好」。
3. **格式正确 ≠ 内容真实**：规则只能校验格式/范围/唯一性，无法判断评分是否真实反映用户偏好（如刷分、误点）。
4. **时效性受年代限制**：数据为历史数据集（2000–2003），Up-to-date 满分仅指「时间戳格式合规」，不代表反映当前状态。
5. **无多版本快照**：HDFS 只保留最新一份产物，历史版本需通过下载报告手动归档。
6. **冲突记录未裁决**：同键不同值的 50,516 条记录被标记但未判定哪条为真，需人工介入。
7. **用户属性未经核验**：`users.dat` 中年龄/职业等由用户自愿填写，格式合法不代表内容准确。

# 迭代二：分类、聚类与降维分析

## 9. 迭代二系统概述

迭代二在迭代一成果（cleaned-v1.0 数据、T1/T2 时间边界、版本管理机制）之上，
新增三类分析能力：

| 任务 | 问题 | 算法（各 2 种，均封装为独立 Agent 工具） |
| --- | --- | --- |
| 分类 | 用户对电影是否会给出 ≥4 分评分 | 逻辑回归、决策树 CART |
| 聚类 | 按历史观影偏好划分可解释的用户群体 | K-Means、DBSCAN（支持噪声点标记） |
| 降维 | 压缩用户偏好画像并比较压缩前后聚类质量、信息保留与资源开销 | PCA、SVD（TruncatedSVD） |

架构要点：

- **计算封装进 Hadoop 容器**：自定义镜像 `lab2-hadoop-ml:1.0`（apache/hadoop:3.4.1 +
  Miniconda Python 3.10 + numpy/pandas/scipy/scikit-learn/matplotlib），
  数据经 HDFS 拉取（迭代一 cleaned 数据），训练/预测通过 `docker exec` 在容器内执行。
- **预训练 + 注册**：一次性训练流水线（`scripts/train-ml.ps1`）生成全部模型、
  坐标、群体摘要与指标，登记到 `ml-artifacts/registry.json`；Agent 工具只做
  预测与查询，**不现场训练**，只返回已登记的实际结果。
- **时间纪律**：画像与统计特征只用训练期(≤T1)；验证期(T1,T2] 选参；测试期(>T2)
  最终评价。分类 F1/F2 统计量只在训练期计算，验证/测试复用训练期统计量。

## 10. 迭代二运行方法

```powershell
# ① 启动（首次自动构建 lab2-hadoop-ml:1.0 镜像，约 5-10 分钟）
docker-compose up -d

# ② 一键预训练（约 5-15 分钟；前置：HDFS 已有 cleaned-v1.0 数据）
powershell -ExecutionPolicy Bypass -File scripts\train-ml.ps1

# ③ 启动后端
powershell -ExecutionPolicy Bypass -File scripts\start-backend.ps1

# ④ 浏览器 http://127.0.0.1:8000/ 顶部导航切换「分类预测 / 用户聚类 / 降维分析」
```

未预训练时，前端三类分区会提示"模型未登记"，查询返回明确状态（这是需求要求的
异常路径，可主动演示）。

## 12. 迭代二实验配置与评价结果

> 详细方案（选型依据/参数网格/口径）见 `docs/迭代二_方案定稿.md`，此处为真实运行结果。

### 12.1 数据切分

| 集合 | 条数 | 正类比例 |
| --- | --- | --- |
| 训练（≤T1） | 901,409 | 57.85% |
| 验证（(T1,T2]） | 67,310 | 54.97% |
| 测试（>T2） | 27,394 | （见评价报告） |

画像：6,004 用户 × 3,678 电影稀疏矩阵。

### 12.2 分类结果（2026-10-19）

| 算法 | 最优参数 | 验证 PR-AUC/F1 | 测试 PR-AUC/F1 | 测试准确率 |
| --- | --- | --- | --- | --- |
| 逻辑回归 | C=0.1, balanced | 0.7248 / 0.6866 | 0.6834 / 0.6666 | 0.6290 |
| 决策树 | depth=None, leaf=50, balanced | 0.7280 / 0.6929 | **0.6950 / 0.6868** | 0.6530 |

Top 特征：LR = Documentary(+0.99)/用户均分(+0.75)/电影热度(+0.51)；
DT = 用户均分(52.5%)/电影热度(27.3%)。测试集 648 条冷启动用户事件、46 条冷启动电影事件、
1,116 条人口属性隔离事件均按既定口径处理并标注。

### 12.3 聚类结果（2026-10-19）

- **KMeans**：验证集选 k=5（轮廓 0.0146），训练群体规模 482/1198/1067/1162/2095，
  群体摘要含均分（3.5-3.6）、类型偏好（Film-Noir/War/Documentary 等）与代表电影；
- **DBSCAN**：选 eps=0.7129、min_samples=5（验证集 3 簇、噪声 48.9%），训练期主簇
  5,788 人 + 216 噪声点（3.6%）；测试期 6 簇、噪声 83.3%。
- 高维余弦空间轮廓系数整体偏低属数据特性，如实报告（详见方案定稿 3.5）。

### 12.4 降维结果（2026-10-19）

- **信息保留（50 维）**：PCA 方差解释率 40.6%、重构误差 0.7704；SVD 40.6%、0.7174；
  各维数（2/10/20/50）完整数据见方案定稿 4.6。
- **资源开销（50 维）**：PCA 3.25s / SVD 2.74s；峰值内存 965MB（中心化稠密矩阵）；
  坐标存储 1.123MB（原始矩阵 1.701MB）。
- **降维前后聚类对照**：KMeans 轮廓 0.0177（原始）→ 0.2515（PCA-50）/ 0.1509（SVD-50）；
  DBSCAN 噪声 3.6%（原始）→ 0%（降维坐标，距离收缩连为单簇）。
- **主要变化方向**：PC1 高载荷为 Star Wars / Raiders of the Lost Ark / Terminator
  等主流大片，解释为"大众电影偏好"方向。
