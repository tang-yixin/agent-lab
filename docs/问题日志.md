### 阶段 2/3：Hadoop 环境与 MapReduce 作业

| # | 问题 | 根因 | 解决方案 | 教训 |
| --- | --- | --- | --- | --- |
| 1 | Docker daemon 未连接（`docker ps` 报错） | Docker Desktop 尚在启动中 | 等数秒后重试即可 | 启动 Desktop 后需等待就绪 |
| 2 | `docker compose` 命令不识别 | 本机装的是独立 `docker-compose`（v5.3.1），非 compose 插件 | 改用 `docker-compose up -d` | 先确认 compose 命令形态 |
| 3 | NameNode 格式化报 `Cannot create directory /data/hdfs/name/current` | 挂载卷 `/data` 归 root，容器 hadoop 用户（uid=1000）无写权限 | 启动脚本加 `sudo chown -R hadoop:users /data/hdfs` | 镜像默认用户与挂载卷权限需对齐 |
| 4 | `chown /data: Read-only file system` | 误对只读挂载的 `/data/raw` 执行 chown，脚本 `set -e` 直接退出 | 只 chown `/data/hdfs`，跳过只读目录 | `set -e` 下任何命令失败都会终止，需精确范围 |
| 5 | 本机 Java 23 与 Hadoop 不兼容 | Hadoop 3.x 仅支持 Java 8/11 | 用 Docker 内置 Java 8；本机 Maven 编译 target 1.8 | 编译版本与运行版本要分开考虑 |
| 6 | 清洗输出混在单目录，评分无法按文件名分类 | 初始设计缺陷：清洗三表数据写同一输出 | 清洗按类型分目录（ratings/users/movies）输出 | 下游依赖文件名/路径时，上游输出结构要提前设计 |
| 7 | 清洗后评分报 `Path is not a file: /user/hadoop/cleaned/movies` | 评分作业未递归读取子目录 | 设置 `mapreduce.input.fileinputformat.input.dir.recursive=true` | 分目录输入需显式开启递归 |
| 8 | 评分把隔离（quarantine）数据也计入 | 隔离目录无类型关键词 | 评分按路径识别类型，`UNKNOWN` 直接跳过 | 隔离数据不属于"清洗后数据集" |

## 经验沉淀（持续更新）

1. **镜像机制要摸清再动手**：`apache/hadoop:3.4.1` 无 SSH、默认用户 `hadoop`、entrypoint 为 `starter.sh`（内部有 `chmod o+rwx /data`），覆盖 entrypoint 时需自行补上等价权限处理。
2. **挂载卷权限**：容器默认用户 uid 与宿主机挂载卷属主不一致时，需 `sudo chown`，且注意跳过只读挂载。
3. **上下游契约**：评分作业依赖"文件名/路径"判断记录类型，清洗作业必须按约定目录输出，并在评分侧开启递归读取 + 跳过非数据目录。
4. **编码**：ml-1m 为 ISO-8859-1（latin-1），HDFS 读写要显式指定，否则中文/特殊字符乱码。
5. **验证要闭环**：每步作业都要用"账目对平"验证（总量 = 清洗后 + 隔离 + 去重），不能只看作业"跑完"。
