# 阶段 1 定稿：五维评分方案与清洗规则

> 版本：`scoring-v1.0` / `rules-v1.0`
> 依据：`scripts/probe_data.py` 与 `scripts/probe_samples.py` 的探查结果。

## 1. 数据探查关键结论

README 声明的"干净"规模为：评分 1,000,209 条、用户 6,040、电影 3,883。
但实际文件被人为注入了脏数据，探查得到的实际规模：

| 文件 | 实际行数 | 声明规模 | 差异说明 |
| --- | --- | --- | --- |
| ratings.dat | 1,150,241 | 1,000,209 | 多出约 15 万条异常记录 |
| users.dat | 6,946 | 6,040 | 多出约 900 条异常记录 |
| movies.dat | 4,465 | 3,883 | 多出约 580 条异常记录 |

### 发现的问题类型（真实存在）

**ratings.dat：**
- 分隔符异常：`::` 之外出现逗号分隔（6,001 条）、字段数 3（缺时间戳，3,751 条）、字段数 5（多出 `EXTRA_FIELD`，3,751 条）。
- 评分异常：`3.5`、`five`、`0`、`6`、空评分，共 27,381 条评分非整数、16,504 条越界。
- 时间戳异常：毫秒级时间戳（如 `978153540000`）、超范围（如 `4102444800`），约 28,881 条非法。
- 重复：完全重复 86,946 条；同一 `(user,movie,timestamp)` 但 rating 不同 4,200 处。
- 跨表：引用了不存在 UserID/MovieID 的记录各 13,878 条。

**users.dat：**
- 分隔符异常：`:` 代替 `::`、字段数 4/6、`EXTRA_FIELD`，共 108 条。
- 编码异常：`Gender=X`（100 条）、`Age=30`（100 条）、`Occupation=99`（100 条）、`Gender/Age/Occupation` 为空（23 条）。
- 邮编非纯数字 140 条。
- 同一 UserID 属性冲突 608 处。

**movies.dat：**
- 分隔符异常：`|` 代替 `::`、字段数 2/4、`EXTRA_FIELD`，共 70 条。
- 标题缺失/空白 58 条、无年份 116 条。
- 类型异常：`UnknownGenre`（174 条）。
- 同一 MovieID 冲突 384 处、同名多 ID 61 处。

## 2. 评分方案（scoring-v1.0）

统一口径：**每维 0–100 分**，通过 Hadoop MapReduce 对"记录级"判定后聚合到"数据集级"。
清洗前后使用**完全相同的公式与口径**，保证可比。

| 维度 | 衡量定义 | 公式 | 说明 |
| --- | --- | --- | --- |
| Accurate | 字段值是否真实合法（在业务允许范围） | 合法记录数 / 总记录数 × 100 | 如评分∈{1..5}整数、时间戳为合法秒级、性别∈{M,F}、年龄∈合法集、职业∈0..20、类型∈已知集 |
| Complete | 必填字段是否非空 | 非空字段数 / 应存在字段总数 × 100 | 缺失/空串/解析失败都计为不完整 |
| Unique | 业务记录是否唯一 | (1 − 重复记录数 / 总记录数) × 100 | 重复 = 完全重复 + 同键冲突 |
| Up-to-date | 时间戳是否落在数据集声明覆盖范围 | 合法时间戳记录数 / 应有时间戳的记录总数 × 100 | 参照 = 数据集发布覆盖期 2000-04~2003-02；毫秒/超范围计为不合规 |
| Consistent | 格式/单位/含义是否一致且跨表无矛盾 | 一致记录数 / 总记录数 × 100 | 分隔符 `::`、字段数、单位(秒)、跨表引用存在性、编码 |

### 综合分
- 采用**加权平均**：Accurate 0.25、Complete 0.25、Unique 0.20、Consistent 0.20、Up-to-date 0.10。
- 权重依据：准确性/完整性直接决定可用性，权重最高；时效性受数据集本身年代限制（2003 年发布），改善空间有限，权重最低。

### 评分局限（需在报告中说明）
- "格式正确"不等于"内容真实"。例如用户自愿填写的年龄/职业，格式合法但未经核验，无法证明真实性。
- 历史数据（2000–2003 年）的"时效性"只能以"是否落在数据集声明范围"衡量，无法达到"反映当前状态"。
- 无法验证的情况：如邮编无外部校验源、电影标题是否拼写正确。

## 3. 清洗规则（rules-v1.0）

三类处置：**修复（fix）**、**去重（dedup）**、**隔离（quarantine）**。

| 规则编号 | 问题 | 处置 | 具体动作 |
| --- | --- | --- | --- |
| R1 | 分隔符异常（逗号/`\|`/`:`） | 修复 | 统一为 `::` 分隔，重新切分 |
| R2 | 字段数错误（3/4/5/6 个字段） | 修复 | 多出的 `EXTRA_FIELD` 丢弃；缺字段按规则补或隔离 |
| R3 | 评分非整数/越界/空 | 隔离 | 无法确定真实值，标记隔离 |
| R4 | 时间戳毫秒级 | 修复 | 除以 1000 转秒级（可确认的量级错误） |
| R5 | 时间戳超范围/非法 | 隔离 | 无法解释，标记隔离 |
| R6 | 完全重复记录 | 去重 | 保留一条 |
| R7 | 同键不同值冲突 | 隔离 | 无法判定哪条为真，隔离冲突组 |
| R8 | 编码非法（Gender=X、Age=30、Occ=99、UnknownGenre） | 隔离 | 超出业务编码集，标记隔离 |
| R9 | 空字段/空标题 | 隔离 | 信息缺失，无法修复 |
| R10 | 跨表引用不存在 | 隔离 | 评分引用了不存在的用户/电影 |
| R11 | 时间戳缺失 | 隔离 | 无法定位时间 |
| R12 | 标题无年份/年份异常 | 修复 | 从标题提取/标注（若能推断则修复，否则隔离） |

**隔离说明**：隔离 ≠ 删除。隔离记录保留在单独文件中，不计入"已修复"，评分时仍按口径体现其影响。
