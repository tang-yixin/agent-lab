# 阶段 7 定稿：时间边界 T1/T2 与版本管理

> 版本：`timeboundary-v1.0` / `versioning-v1.0`

## 1. 时间边界 T1/T2

根据 `scripts/probe_times.py` 对合法秒级评分时间戳的分布统计：

- 数据覆盖：**2000-04-25 ~ 2003-02-28**（UTC）
- 评分高度集中在 2000 年下半年（尤其 2000-11、2000-12），之后逐步衰减。

### 采用的边界

| 边界 | 含义 | 取值 | 时间戳（秒，UTC） |
| --- | --- | --- | --- |
| T1 | 训练期截止 | **2000-12-31 23:59:59** | 978307199 |
| T2 | 验证期截止 | **2001-12-31 23:59:59** | 1009843199 |

### 三段划分

| 区间 | 范围 | 用途（供迭代二/三） |
| --- | --- | --- |
| 训练期 | ≤ T1（2000-12-31 前） | 训练分类/聚类/降维模型 |
| 验证期 | T1 < t ≤ T2 | 调参、选模型 |
| 测试期 | > T2（2002 年起） | 最终测试，**不得用于训练** |

### 选择依据
- 数据以"年"为自然单位，按年切分边界清晰、可解释、不易混用。
- 2000 年数据最密集（约 85%），足以支撑训练；2001 年作为验证期；2002 年起作为独立测试期。
- 边界取整日/整年，避免同一秒被切分到两段。
- **硬性约束**：后续迭代不得混用不同时间段的数据构造训练输入；测试期数据永不进入训练/验证。

## 2. 版本管理

所有产物保留版本信息，避免混用：

| 产物 | 版本号 | 说明 |
| --- | --- | --- |
| 原始数据 | `raw-v1.0` | ml-1m 原始文件（只读，不改动） |
| 清洗后数据 | `cleaned-v1.0` | 阶段 3 产出，随规则版本联动 |
| 清洗规则 | `rules-v1.0` | 阶段 1 定稿 |
| 评分配置 | `scoring-v1.0` | 阶段 1 定稿 |
| 时间边界 | `timeboundary-v1.0` | 本文件定稿 |
| 任务标识 | UUID（每次任务生成） | 随评估报告落盘 |

## 3. 版本与边界落盘约定
- 配置将写入 `config/` 目录（JSON），供 Agent 与 Hadoop 作业读取。
- 每次清洗任务记录：任务 UUID、输入数据版本、规则版本、评分配置版本、T1/T2、输出数据版本，一并写入评估报告。
